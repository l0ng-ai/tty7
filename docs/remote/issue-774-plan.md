# Issue #774：远程会话可靠性修复方案

关联：https://github.com/l0ng-ai/tty7/issues/774

Draft PR：https://github.com/l0ng-ai/tty7/pull/775

状态：当前优先修复“断线后回到原来的工作”，不再优先扩展维护保护。已修复恢复失败误建 Shell、迟到附着误关原进程、旧凭据/旧代次结果落地，以及 Windows 处理远端 PTY 时的缩放配置；Windows 原生 SSH → Linux 实测覆盖原工作区/原进程恢复、实际传输中断和 Vim 未保存内容恢复、`:wq` 保存退出。当前协议仍为 c10p8。btop 长输出溢出后的完整终端恢复、原始启动事故的根因等仍未解决，PR 保持 Draft，不自动关闭 issue。具体结果、复验方法与剩余工作见第 10 节。

## 1. 目标与证据边界

保留现有“本地 daemon + 原生 SSH + 远端 server”架构，统一连接生命周期，明确云端状态归属，再完善终端恢复与升级。

核心承诺：本地掉线、休眠、关闭窗口再打开，不应改变云端正在运行的工作，也不应悄悄抢占其他客户端的工作区。

| 状态 | 保存位置与恢复原则 |
| --- | --- |
| Shell、Vim、btop 等真实进程 | 远端托管；客户端断开不终止进程 |
| 工作区布局、pane 身份 | 远端为权威；本地缓存不能覆盖未知的远端状态 |
| 屏幕、光标、终端模式 | 从一致的终端快照恢复，不依赖有限历史字节包含初始化指令 |

远端机器重启或进程本身退出后，不承诺复活原进程。恢复布局、重新打开 Shell，不等于恢复运行状态。

本次静态调查以运行时代码基线 `cebd871cb4b3814356c63a59e3a3a4c6f4d4d300` 为准。用户截图中 server 文件名为 c7p6，与该基线控制协议版本存在差异，不能直接认定截图对应相同构建。远端启动失败的实际原因及本次“云端状态丢失”的完整因果链尚未独立证实；没有在用户远端进行破坏性复现。

已有相关报告包括 #716（工作区状态）、#579（旧同步删除问题）、#351（旧版本替换）、#498（重连错误）、#430（Vim 退出错位）、#722（滚轮行为）。已关闭问题只能作为回归参考，不能视为当前版本仍存在相同缺陷的证据。

### 调查发现与修复对应

| 发现或症状 | 证据边界 | 对应措施 |
| --- | --- | --- |
| 多个远端通道各自准备 server；临时文件仅区分 PID；rename 失败会删除正式文件 | 源码存在可构造的竞争路径，未实机复现误删 | 双层安装协调、唯一临时文件、安全发布 |
| 工作区附着失败仍记入 attach_sent，主机存活时错误被清除 | 当前源码路径可见 | 分层状态、失败分类和工作区独立重试 |
| 初始协议协商与 Hello 缺少完整的客户端期限控制 | 对保持通道但不回复的服务端可能永久等待 | 分阶段期限、取消及底层资源回收 |
| 异步连接结果缺少目标/代次约束，断开后迟到任务可能重新挂接 | 源码竞争路径，需确定性测试 | 连接代次、结果绑定、取消失效 |
| 自动重连可能重新附着已被其他客户端接管的工作区 | 当前附着与接管语义混合 | Resume/TakeOver 分离、服务端凭据校验 |
| 远端升级通过终止旧 daemon 切换 | 现有行为会结束其托管进程，不等于已证明用户数据被删除 | 连接与维护分离、延后破坏性升级、验证 handoff |
| Windows→Linux Vim 的冒号与后续字符错位 | 客户端平台开关与真实 PTY 来源不一致是候选原因，待字节序列复现 | 按实际 PTY 能力启用光标修正 |
| btop 等 TUI 重连后异常滚动 | 隔离 PTY 的 9 MiB 确定性输出已证实 8 MiB 回放会丢失备用屏幕/鼠标初始化；不等于复现用户 btop 原现场 | 完整终端快照与有序增量 |
| 上传进度、长错误状态条越界 | 用户截图可见；宽度/裁剪约束需 UI 验证 | 受约束布局、阶段状态、可展开详情 |

## 2. 每台远端一个连接协调器

将 UI、自动重连、pane 恢复、安装流程中的连接决策收敛到本地 daemon。窗口只提交意图并订阅状态。“一个”指生命周期管理者，不限制 SSH 通道数量。

```text
窗口 / 工作区 / pane
        ↓
本地 daemon：远端连接协调器
        ↓ SSH
远端 server
        ├─ 工作区与控制权
        ├─ PTY 与真实进程
        └─ 终端状态与输出
```

- 多个 pane 同时恢复，共享一次连接、认证和 server 准备流程。
- 安装、启动、替换 server 由协调器调度；普通 pane 不再各自触发安装。
- 每次连接携带 attempt_id 和连接代次；完成回调及事件必须验证代次仍有效。
- 主动断开、切换目标后，迟到结果只能释放资源，不能重新挂回 UI。
- 手动连接的结果绑定发起时的目标，禁止根据当前连接选择决定结果归属。
- 取消一个窗口的等待，不取消其他消费者仍然需要的共享连接；没有消费者时按连接意图回收资源。

分别管理连接配置标识、远端持久身份、server 实例标识和连接代次。远端持久身份应识别用户环境而非仅识别物理机器；实例标识用于判断 daemon 重启。持久身份只能在 SSH 信任验证后使用，不能仅凭 IP 或远端声明的 UUID 合并配置和权限。身份尚未发现时按连接配置合并请求，识别后再安全关联。

### 超时、取消与重试

SSH 连接、通道打开、协议协商、Hello、工作区附着分别设置期限；明确各阶段及整次自动连接的时间预算。用户输入认证信息的等待与网络超时分开计时。

超时或取消必须关闭对应底层通道并结束阻塞工作，不能仅让 UI 停止等待。共享连接只回收该操作拥有的资源。

| 情况 | 策略 |
| --- | --- |
| 网络中断、暂时启动失败 | 有上限的退避并加入随机抖动，保留最后错误 |
| 密码、密钥、主机指纹问题 | 等待用户处理，不持续重试 |
| 工作区被其他客户端接管 | 停止自动争抢 |
| 用户主动断开 | 停止自动连接，直到新的明确连接意图 |
| 有副作用的操作结果未知 | 查询操作结果，不盲目重复执行 |

## 3. 分层状态与真实就绪条件

| 层级 | 典型状态 |
| --- | --- |
| 主机 | 未连接、认证中、准备服务、握手中、可通信、退避、需处理 |
| 工作区 | 获取控制权、同步布局、就绪、被接管、同步失败 |
| pane | 等待附着、恢复快照、可交互、进程已退出、恢复失败 |

UI 示例：“已连接服务器，正在恢复终端：7/10。2 个正在重试，1 个进程已退出。”

- 修复 finish_reclaim：失败不能当作附着成功；暂时失败进入工作区自己的重试状态。请求已发送与附着已完成使用不同字段表达。
- 主机存活不能清除工作区/pane 错误；错误只在对应层级恢复后解除。
- “重试”只重置失败层级，不默认重连所有终端。
- 控制权有效、布局同步完成、终端恢复到一致位置后，才开放对应输入与操作。
- 失败保留最后成功画面，标记其为断开后的旧画面，不清空成一个看起来正常的新终端。
- 保留现有 pane 自动重试能力，将其纳入统一状态模型，而非误认为需要从零补齐。

## 4. 控制权、布局与操作结果

### 恢复和接管分离

- Resume：恢复本客户端仍有效的控制权。
- TakeOver：用户明确点击接管后执行。
- 远端签发带代次的控制凭据。接管使旧凭据失效，由服务端拒绝旧客户端输入、resize、布局修改和进程操作。
- 凭据校验覆盖控制通道及 pane 通道，不能只依赖旧 UI 停止发送。可信 CLI/管理入口需明确其授权语义，不能成为无意绕过路径。
- 控制权失效或无人连接不终止 PTY；服务器重启时不得继续接受旧实例凭据。

### 远端布局为权威

- 远端布局带版本号，本地修改带预期版本；冲突时重新读取，不无条件整树覆盖。
- 本地缓存仅作占位。连接失败、同步未完成或远端状态未知时，禁止以本地空布局覆盖远端。
- pane 恢复失败只标记失败，不从远端布局删除。
- 删除工作区、关闭 pane 必须来自明确操作，不能从“恢复时没找到”推导。
- 保留已有同步代次与删除保护，增加 #716/#579 相关回归场景。

### 有副作用的请求可查账

创建/关闭 pane、接管、维护升级等请求带操作 ID。远端在约定的保留窗口内记录结果并去重；协议明确记录的持久化范围、过期与 server 重启后的结果未知语义。超时后先查询，避免重复创建或重复终止。

终端输入不能直接套用普通请求重试。第一阶段断线时不自动补发未确认输入，避免命令执行两遍；若以后支持输入续传，需要独立设计序号、确认和去重协议。

## 5. 安装与升级安全

### 先修复安装竞争及诊断

- 每次操作使用随机唯一临时文件，并排他创建。
- 本地按远端协调安装；远端也需要安装锁，覆盖两台客户端同时安装的情况。
- 获取锁后重新检查服务与目标文件，避免锁外检查结果过期。
- 完成上传、完整性校验、可执行性及协议校验后才发布。
- 删除“任意 rename 失败就删除正式文件”的回退；发布失败保留旧可用版本。
- 清理只针对本次操作创建的临时文件。锁恢复采取保守策略，不能仅凭等待超时删除仍可能使用中的锁。
- 检查启动命令退出状态，保留有界且权限受限的启动日志。
- 健康检查完成真实 Hello，核实实例与能力，而非仅检查文件、进程或 socket 存在。
- 进度分为下载、上传、校验、启动、握手；上传 100% 不等于安装成功。
- 启动超时保留可诊断原因，不默认通过杀进程恢复。

### 连接与维护分离

- 兼容 server 优先复用，连接不强制升级。
- 升级进入独立维护状态，与安装和普通重连协调互斥。
- 候选版本使用独立路径，不覆盖正在运行的版本；在可行范围内使用隔离端点预检，避免与现有 daemon 争用正式 socket。
- 校验候选能力后决定是否安全切换；保留旧版本和明确的活动版本选择。
- 优先验证现有 handoff 是否适用于远端，覆盖 PTY、输出状态、布局与客户端重新附着。
- handoff 未验证或协议不兼容时，默认延后需要终止会话的升级。
- 用户选择破坏性维护时，展示受影响工作区和运行终端，明确确认后再操作。

二进制回滚不等于会话回滚。已经被杀掉的 Vim 或计算任务不能靠恢复旧二进制复活；切换失败应明确哪些状态仍可保留、哪些结果未知。

## 6. Vim 光标与 TUI 恢复

### Vim：按实际 PTY 来源启用兼容修正

当前光标修正按客户端 cfg!(windows) 启用，不能准确代表远端 PTY 行为。

- pane 协商传递实际 PTY 后端或明确兼容能力。
- Windows 客户端连接 Linux 原生 PTY，不启用 ConPTY 专用光标修正。
- Windows 本地 ConPTY 保留必要修正并独立回归。
- 未知来源采用保守策略，不盲目套用 Windows 修正。
- 先采集最小终端字节序列，复现冒号与 wq 分离，再验证修复；同时覆盖 #430 的原有行为。

此项可以作为独立小补丁提前交付，不依赖完整快照架构。

### btop：真正的终端快照与有序增量

当前 Snapshot 消息实际承载历史字节片段。初始化序列被历史上限淘汰后，重放不保证恢复备用屏幕、鼠标模式和光标状态。

1. 远端持续维护每个 pane 的终端状态，优先复用项目已有解析器，避免另写简化解释器；评估独立无 UI 状态模块的边界。
2. 快照覆盖主/备用屏幕、光标与保存光标、滚动区域、终端模式、尺寸及恢复所需解析状态。定义有版本的协议结构，不直接暴露解析器内部内存布局。
3. 输出和 resize 使用同一有序事件序列；明确快照对应的尺寸和事件位置。
4. 客户端获取序号 N 的快照，再接收 N 之后的事件。快照生成与订阅注册必须形成一致边界，不能在两者之间漏掉输出。
5. 交接无丢失、无重复；增量超出保留窗口则重新获取快照。慢消费者使用有界缓冲，不能无限消耗内存。
6. 恢复完成并确认就绪后开放输入；由有效控制者决定尺寸，避免多个观察者互相 resize。

必须覆盖控制序列或 UTF-8 被分块时的解析中间状态。历史恢复不得重复触发剪贴板写入、通知、终端查询回复等副作用；明确唯一响应者和恢复期间的副作用抑制规则。

历史可以有上限，但当前终端模式不能随历史淘汰。CPU、每 pane 内存、快照大小和恢复延迟需实测确定预算。

只补发 ALT_SCREEN 等少数模式可作为过渡缓解，不能作为完整修复的验收标准。

## 7. UI 与诊断

- 状态容器限制宽度；文本允许收缩和换行，操作按钮保持可见。
- 进度条裁剪在轨道内，传输与启动分别展示。
- 默认简短原因，路径、stderr、堆栈放入可展开详情。
- 根据错误提供重试此终端、重新认证、接管、查看启动日志等对应操作。
- 结构化诊断包括连接代次、阶段、耗时、远端实例、工作区/pane、错误类别与重试原因。
- 默认不记录终端内容、密码或私钥；诊断导出提供脱敏预览，日志采用有界保留。

## 8. 实施顺序与兼容策略

每阶段独立评审、独立验收，避免一个巨型补丁同时替换所有路径。

| 阶段 | 交付内容 | 主要代码范围 |
| --- | --- | --- |
| 1：止血 | 安装竞争、握手期限、迟到回调、附着失败重试；Vim 和状态条小修 | daemon/install、daemon/ssh、remote_connect、remote_workspace、terminal/remote |
| 2：统一生命周期 | daemon 侧协调器、分层状态、取消与重试策略 | 本地 daemon、远端连接 UI、HostLinks |
| 3：保护远端工作 | Resume/TakeOver、服务端凭据校验、布局版本、操作去重 | 控制协议、host/server、tree_sync |
| 4：可靠恢复屏幕 | 有版本的快照、有序事件、无缝增量交接 | daemon/pane、终端解析与恢复 |
| 5：安全维护升级 | 分阶段发布切换、远端 handoff、失败恢复 | installer、handoff、维护 UI |

协议扩展通过能力协商启用，不兼容变更按项目规则升级协议版本。新客户端连接旧服务时明确能力限制，不能静默声称提供新可靠性保证；旧客户端不能绕过新服务端的控制权保护。缺少安全升级能力时保守延后维护，而非强制终止会话来获取新能力。

需要通过原型及测试确定的实现细节：远端安装锁及崩溃恢复、终端状态导出/导入接口、快照资源预算、远端 handoff 的失败边界。以上是必须关闭的设计验证项，不是已实现能力。

## 9. 测试与验收

优先扩展现有 FakeRemote、工作区状态和协议测试，使用可控调度/屏障构造竞争，并通过可控 SSH 环境进行集成测试。不要仅依赖真实网络偶发触发竞态。

| 场景 | 必须满足的结果 |
| --- | --- |
| 同时恢复 10 个 pane | 安装不竞争，不重复创建进程；每个 pane 状态准确 |
| 两台客户端同时首次安装 | 不共享临时文件，不误删可用版本；锁内重新检查 |
| Hello 阶段服务端不回复 | 在期限内退出，资源释放，可重新连接 |
| 连接 A 后切换 B，A 迟到成功 | A 不写入 B，不改变当前选择 |
| 连接过程中主动断开 | 后台完成不能使连接复活 |
| 单个工作区附着暂时失败 | 主机保持连接；失败可见且可独立重试 |
| 两客户端交替上线 | 自动恢复不抢占；旧凭据不能继续输入、resize 或修改布局 |
| 操作已执行但响应丢失 | 查询得到结果；不重复创建/终止 pane |
| 休眠、断网、VPN 切换 | 远端进程未退出的前提下恢复原 pane 和进程 |
| btop 输出超过回放上限后重连 | 备用屏幕、鼠标与滚轮行为正确 |
| 快照期间持续输出、resize、跨帧控制序列 | 屏幕与状态一致，无丢失/重复事件，无重复副作用 |
| Windows→Linux Vim 执行 :wq | 字符与光标位置正确；本地 ConPTY 无回归 |
| 上传中断、磁盘满、候选启动失败 | 旧可用版本和原有会话不被误删、误杀 |
| 布局同步中断或本地缓存为空 | 不删除远端工作区和 pane |
| 窄窗口、高 DPI、超长错误 | 内容不越界，关键操作可用 |
| 新旧客户端/server 混用 | 能力协商明确；不绕过控制权保护，不隐式破坏性升级 |
| handoff 成功及各阶段故障注入 | 明确保留或失败边界；不能将新建 Shell 视为原会话恢复 |

实机矩阵至少覆盖 Windows 客户端→Linux server、Windows 本地 ConPTY，以及受支持的 macOS 远端路径。会话保持核对 pane ID、进程身份和应用状态，不只看“又出现了 Shell”。资源测试覆盖多 pane 持续输出、慢消费者与重复断线后的内存/通道回收。

### 第一阶段首批改动

- 安装临时文件改为 PID + 每次操作随机 UUID；SSH 安装、启动准备与维护入口按连接 key 共用进程内互斥锁。
- 安装发布失败只清理本次 staging 文件，不删除正式二进制，也不进行破坏性重试。SSH 发布使用同目录的 `mv -f`，保留现有目标的原子替换语义，并拒绝目录目标。
- SSH 启动命令检查退出状态；首次启动也报告启动阶段，避免一直停在上传 100%。
- TCP/Unix socket 控制 Hello 的完整读写交换增加 15 秒总期限；分片字节不能延长总期限，结束后恢复原 socket timeout，避免影响长期控制连接。
- 手动连接携带 attempt ID；自动重连也验证代次、主动断开及是否仍有工作区需要该连接。迟到结果不能重新挂接或覆盖新目标。
- 自动重连不在后台连接阶段提前发送 WorkspaceAttach；手动连接和自动重连统一走附着流程，保留已知的 preempted 标记。
- 附着失败不再记作成功；按工作区保留错误并退避重试，主机心跳不能清除这份错误。旧连接的附着结果不能更新新连接；成功附着后才恢复 pane/布局。
- Windows 客户端读取 routed Linux/macOS/WSL 或新建原生 SSH 输出时，不启用本地 ConPTY 光标修正；本地 ConPTY 路径保留原有行为。
- 首页和工作区状态条增加宽度、文本收缩/换行及按钮约束；进度条裁剪在轨道内。

本批未修改控制/终端协议版本及消息格式，也未在用户远端安装、重启或终止 server。

### 第二批：连接准备与取消清理

- 修正 `RemoteHost::over_tcp/over_unix` 经过泛型 `connect_with` 绕过 socket Hello 期限的问题。实际 UI 连接路径现复用受限握手；增加不回复的 loopback peer 回归，验证超时且 socket 释放。
- 本地 daemon 安装入口按连接 key 使用并发准备批次。同一 SSH 连接代次共享完整准备结果，包含成功及普通失败；10 个并发恢复请求不再依次重复同一套探测、安装、启动或失败操作。
- 批次只在仍有调用者时存在，不永久缓存“远端健康”。新的 SSH 实例不复用旧结果；重启/替换与准备互斥，维护即使失败也使已有准备结果失效。
- 取消排队调用者不等待正在执行的安装结束，也不取消其他调用者。取消/拒绝确认的结果不替其他窗口作决定：后续调用者可使用自己的确认入口重新准备。
- 路由关闭时同时取消认证 broker 和安装确认 relay，唤醒其等待者并拒绝迟到问题/回答。认证 future 中途丢弃也清除 pending，避免残留状态继续暂停网络超时计时。
- 安装增加阶段间取消检查；下载或上传返回后发现取消，不继续发布/启动。上传失败或发布前取消只尽力清理本次唯一 staging，不删除正式文件。
- 已经明确发起的维护在停止 daemon 前响应取消；如果停止步骤已执行，则继续完成启动，不因窗口消失把服务器留在半途。这不提供保会话升级，也不扩大维护授权。

本批是批次协调和局部取消清理，不是完整主机 actor：尚未统一长期状态订阅/进度广播，也没有在所有 SSH/SFTP/下载读写内部立即中断。第二批的取消入口以本地路由实际关闭为准；UI attempt 到路由关闭的接入见第三批。没有修改协议、用户已安装客户端或用户远端服务器。

### 第三批：UI 尝试所有权与认证问题生命周期

- 手动连接和自动重连使用不可克隆的 UI 尝试所有者，后台仅持有取消句柄。取消、切换目标、销毁窗口会结束相应尝试并关闭其本地路由 socket；不关闭 daemon 内其他调用者共享的 SSH 传输。
- socket 在发送路由头之前登记；取消与登记并发时，迟到 socket 会立即关闭。取消覆盖已登记路由的协商、Hello 和工作区列表等待，连接成功后由 UI 确认当前代次并移交路由，销毁尝试不误断开已经接受的连接。
- 主动断开某台主机取消该应用所有窗口内该主机的未完成尝试；关闭单个窗口仅取消自己的手动尝试。自动重连在该主机最后一个窗口关闭时退出，即使其他主机仍让 supervisor 运行。
- 尝试登记放在 GPUI 应用状态中，而不是进程静态变量；独立应用实例/并行测试不相互阻止或取消连接。同主机手动连接进行中，不重复启动自动重连；手动重试会撤销原自动尝试。
- GUI 密码与安装确认等待复用路由取消句柄，每 100 ms 检查取消；确认超时、连接取消或接收者退出后，问题失效、迟到回答不再发回路由。
- 认证框按问题 ID 追踪失效并关闭，旧问题的监视任务不会关闭新问题；提交失效密码框不会写入钥匙串。清理认证队列里的失效问题，避免它们阻塞其他主机的问题。
- 首次从本地窗口连接新服务器时，认证问题也能找到发起连接的窗口，不再只寻找尚未存在的远程工作区。

本批没有修改线协议或操作用户已安装客户端/远端 server。取消粒度仍有边界：本地 daemon 引导和 socket 建立只有阶段检查，已进行的 SSH/SFTP/下载调用不保证立即中断；原生安装确认对话框没有程序化关闭入口，可能仍需用户关闭，但后台不再等满 180 秒，其迟到确认无效。长期主机协调器、按尝试归属的进度广播以及 pane 路由的统一生命周期仍待后续实现。

### 第四批：恢复凭据与控制连接拒写

- 控制协议升级为 **c9**，pane 协议仍为 **p6**。自动恢复发送 `WorkspaceResume`，用户明确接管才发送 `WorkspaceTakeOver`；不兼容旧客户端在 Hello 阶段被拒绝，不能静默改用旧的附着语义。此批不自动替换已运行的旧 server。
- server 为工作区签发不透明恢复凭据；恢复校验凭据，不以主机名或客户端声明的 token 作为恢复授权。凭据在 socket 断开后保留到本 server 实例结束；接管轮换凭据，即使新客户端随即离线，旧客户端也不能自动取回工作区。
- 客户端按连接配置 key、远端工作区和 server 实例匹配凭据，在私有配置文件 `remote-resume.json` 中原子保存；重启客户端后可以恢复，换 server 实例不能误用旧凭据。协议 Debug 输出对凭据脱敏。
- Busy 是被占用状态，不进入自动接管/重试循环。收到有效附着结果后才同步布局并恢复 pane；保持连接代次校验，迟到结果不能覆盖新连接。
- 已被认领工作区的树写入与控制权切换共用互斥边界，非当前控制连接不能修改其布局。断开的连接不能从工作队列中迟到地获取控制权；不存在的工作区不会产生幽灵凭据。
- 修复同一客户端重连后的迟到 Detach：只有实际释放 live seat 的连接才能清除机器树中的附着记录，旧连接不能凭相同客户端 token 清掉新连接。
- CLI 树管理操作通过显式 `ManageWorkspace` 入口。该入口的信任基础是同一 OS 用户的私有 socket / 已认证 SSH 账号，**不是**针对能以该账号执行任意命令的对手的安全沙箱；GUI 后台写入不使用该入口。尚未被认领的工作区保留已有本地树编辑语义。
- 替换/移除 HostLinks 时立即使旧控制连接失效并关闭其本地 socket；reader 回收放在后台，避免把最多 500 ms 的回收等待放在 UI 线程。同一个 host 对象重复登记不关闭它。

### 同批 pane 流加固（不是工作区凭据贯通）

- 单个 pane 的附着/脱离与 Input、Resize、AuthResponse、Kill 通过同一控制者互斥边界执行，避免“先检查代次、后操作”之间被另一个附着插入。
- 旧控制代次不能再输入、resize 或 kill；已脱离但数字代次相同的流也不再有效。已经获准的命令执行结束后，新控制者才能完成附着；互斥不持有输出状态锁，输出仍能排空。
- 流上的 Kill 只能作用于自身 pane，并在控制者校验内执行，不再等 detach/新附着之后才执行。流不能越界关闭别的 pane。

**边界：**以上代次属于单个 pane，不是工作区凭据。工作区 TakeOver 尚未在服务端直接撤销所有旧 pane 流；新建 pane 路由、Attach、独立 SendInput/Kill 管理请求还没有贯通工作区授权。不能宣称旧工作区客户端已被全面隔离。PTY 输入写入仍可能阻塞，后续统一 pane 生命周期需要补充有界输入调度/期限，不能将工作区全局切换锁直接持有到阻塞写结束。

### 第五批：工作区权限贯通 pane 与关闭确认（2026-09-05）

- 协议升级为 **c10p7**。`WorkspaceLease` 除持久恢复凭据外，另发只在内存持有的 pane 凭据；每次 Resume/TakeOver 都轮换 pane 凭据。持久恢复凭据不能直接用来操作终端。
- 远程 GUI 的 Spawn、Attach、Input、Resize、AuthResponse、独立 SendInput/Kill 使用当前工作区授权；不能退回无凭据写入或管理入口。新进程在发布前绑定工作区，客户端自报的 owner 标签不是授权依据；既有 pane 仅能从权威树中的唯一归属建立绑定。
- 接管完成前撤销旧 pane 凭据并关闭其登记的 pane socket，不终止原 PTY、不关闭其他工作区共享的 SSH 传输。旧客户端即使不读 Preempted 通知，或重新打开 socket，也不能使用旧凭据继续操作。
- 控制连接断开、Detach、删除工作区也使 pane 凭据失效；旧连接的迟到释放不清除新连接的凭据。GUI 替换主机连接、Busy、Preempted 时清理内存授权，迟到附着结果不重新写入已被抢占的授权。
- 工作区操作仅在实际执行期间持有读许可，不在等待网络消息时占用。接管遇到未完成的 PTY 命令会非阻塞地返回可重试错误，原控制权保持不变；不会持有主机接管锁等阻塞输入结束。工作区删除也先要求在途命令结束，失败不先删树或撤销权限。
- 无授权连接不能打开可写 pane、输入或关闭 pane；只读查询不要求 pane 凭据。本地 GUI、CLI 和显式维护使用 `PaneAccess::Manage`。旧版维护仅在只读版本探测后按旧协议发请求；远程 GUI 不降级。本批不重做 SFTP/转发等主机管理接口，仍基于同 OS 用户的信任边界，不是针对同账号任意程序的安全沙箱。
- 独立 Kill 新增 `KillAck`，SDK/GUI 等待有期限的确认并传播拒绝，不把成功写入 socket 当作成功结束进程。重复关闭已不存在的 pane 可确认完成，但过期凭据仍会被拒绝。
- 工作区停止/删除先读取服务端权威树，等待其 pane 的 Kill 确认，删除时再等待 WorkspaceRemove 确认，最后关闭窗口/清理本地入口。无连接或操作失败保留入口并显示错误，阻止重复提交；补齐中英日提示。后台树同步的 WorkspaceRemove 本身仍不隐式杀进程。

**本批边界：**这补齐第四批缺失的 pane 授权链路，但没有实现布局 revision、操作 ID/结果查询或多步骤关闭的事务性。并发新建/改动布局、响应丢失、跨工作区转移进程还需要明确的操作协议；停止多个 pane 中途失败时，前面已确认停止的 pane 不会回滚。PTY 输入仍未改为有界队列，持续阻塞的输入可能使接管暂时失败。完整快照和保会话升级仍未修复。

### 第六批：远端空闲维护保护（2026-09-05）

- 服务端在同一创建屏障内检查实例、在途 Spawn 和 pane 注册表。只有不存在任何 pane 且没有正在创建的 pane 才能接受退出；检查通过后禁止新建，持有屏障直至退出，避免“检查空闲后又创建终端”的竞争。已退出但仍保留在注册表的 pane 也会阻止维护。
- 远端 Installer 删除按进程名称查找并发送 SIGTERM 的关闭路径。候选程序的 `--prepare-idle-restart` 只连接当前配置的端点，先只读探测能力，再请求该实例空闲退出；不支持的新旧版本组合、忙碌、错误实例、EOF 或缺少确认均不触发强制关闭或继续启动。
- 得到确认后等待端点退出，再启动候选；如果另一实例出现则报告冲突，不继续关闭它。停止步骤已提交后继续完成启动，不因发起窗口关闭而中断。进程不存在时也可启动，但没有跨客户端维护事务或回滚保证。
- 维护启动完成必须通过 `--check-running` 的真实 pane Version、控制 Hello/Ping 和再次 Version 检查：build/协议正确，两个端点属于同一实例，检查期间实例不变。不再把桥接 EOF、socket 存在或退出码为零当作维护成功。控制与 pane 共用进程实例 ID。
- 现有 Unix handoff 遇到不能迁移的 Native SSH pane 时改为拒绝并保留该 pane，不再先关闭它；handoff 收集期间也阻止新建 pane。这只是拒绝危险路径，尚未实现完整的冻结、状态 ABI、候选接收或失败回滚。
- 更新中英日远端重启/替换提示：只有空闲且支持安全检查才能切换，否则保留现状并延后。旧 server 不支持此能力时，即使空闲也不自动关闭，需要用户显式结束会话并停止旧 server 后再更新。

**本批边界：**仅覆盖远端 Installer 的重启/替换路径及 Native SSH handoff 拒绝保护，不是运行中会话无缝升级。显式本地破坏性重启及 CLI 管理 Shutdown 仍是独立的管理操作。首次安装的 `ensure_daemon` 仍使用旧探测，完整阶段绝对期限、跨客户端安装锁、启动日志留存及回滚尚未完成。

### 当前交付：原会话恢复链路（2026-09-05）

优先级：先让本地断开后能继续云端原来的工作，再解决长时间 TUI 的状态恢复和连接就绪体验；安装锁、维护升级等不再排在前面。

- 远端恢复只有收到完整、且明确指向当前 pane 的 `no such pane <id>`，才可判定原 pane 不存在。过期凭据、权限拒绝、半个消息、超时或连接中断保留原 pane ID，显示失败等待恢复，不启动替代 Shell，也不重复启动 agent。Attach 首帧复用绝对读写期限，不能靠持续发送碎片无限延长。
- 已附着的旧进程只由这次恢复借用：关闭占位或结果迟到时只发送 Detach、释放连接，不发送 Kill。真正由本次 Spawn 创建但无人接收的进程仍按归属清理。
- 待恢复占位每次尝试取当前工作区凭据，成功重新获取控制权后自动重试原 pane；新建 Shell 的不确定结果不自动重试。占位 attempt ID、pane relink generation、当前连接/工作区凭据三层检查，拒绝旧尝试覆盖新结果或接管后的连接。
- Windows 的原始远端 Unix PTY 不再使用 ConPTY resize 语义；配置重载和原位重连也保留正确后端配置。先用确定性测试复现同样缩放后光标差一行，再修复。
- Attach 请求中的尺寸目前被服务端有意忽略，以旧几何回放；客户端新附着现在主动随后发送当前 viewport 的 Resize，不依赖首次 UI 布局才纠正。实测曾停在旧 120×36，修复后在 80×24 恢复并完成 Vim 命令。
- 显式 `server_command` 路由不再准备默认安装、探测/复用同 SSH 连接上另一个 daemon 的默认 socket。首次 Windows 实测因此走错默认安装路径而失败；修复后控制与 pane 均进入指定隔离实例。它不是用户原始默认连接启动失败的已证实根因。
