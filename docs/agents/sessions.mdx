Coding agents keep their own conversation history, addressed by a session id.
Because tty7's hooks learn that id, it can do three things with it.

## Resume after a restart

When the server goes away — a reboot, a crash, a deliberate restart — the shells
go with it. Panes that were running an agent relaunch the conversation on
restore instead of coming back to a bare prompt:

```bash
claude --dangerously-skip-permissions --resume 8f3c…
```

The original launch flags are replayed, so the pane comes back the way you
started it, not the way the defaults would.

Supported for every recognised agent except Aider. Turn it off with
`restore_agent_sessions: false`.

<Note>
  Resume needs the agent's hooks installed, since the session id comes from
  them. [Installing hooks →](/agents/status)
</Note>

## Fork a live session

Forking branches a running conversation into a second, independent one. The
original keeps going untouched; both continue separately from the same history.

Right-click a **pane** to fork into a split — the menu offers a placement —
or right-click the **tab or sidebar row** to open the fork in a new tab.

| Agent | What tty7 runs |
|---|---|
| Claude Code | `claude --resume <id> --fork-session` |
| Codex | `codex fork <id>` |
| TraeCode | `traecli fork <id>` |
| Grok | `grok --resume <id> --fork-session` |
| Qoder CLI | `qodercli --resume <id> --fork-session` |
| Qoder CN CLI | `qodercn --resume <id> --fork-session` |
| OpenCode | `opencode --session <id> --fork` |
| Oh My Pi | `omp --fork <id>` |
| Prime Agent | `prime-agent --fork <id>` |

It is the agent's own fork command, run in a new pane — nothing is copied by
tty7 itself.

<Warning>
  A fork duplicates the whole transcript in the agent's session store, so
  forking repeatedly costs real disk. A pane on a
  [remote machine](/remote/workspaces) cannot fork, because the command would
  run against the local agent.
</Warning>

## Hand off to another agent

When an agent's context is full or it's stuck, a handoff gives its task to
another agent: Codex taking over from Claude Code, or a fresh session of the
same agent. The old agent keeps running.

Start one from any of these:

- **Agent: Hand Off…** in Search Everywhere, then pick the agent. Hold
  <kbd>⌥</kbd> (<kbd>Alt</kbd>) as you pick to open it in a split instead of a tab.
- Right-click the tab or sidebar row, then **Hand Off to**.
- `tty7 handoff %PANE --to codex [--split right|down|tab]` from a script or
  another agent. See the [reference](/cli/reference#tty7-handoff-pane-to-agent-split-right-down-tab).

tty7 writes a markdown handoff document, opens a new tab in the same directory,
starts the agent there, and tells it:

> You're taking over a task from Claude Code. Read `<path>` first, then continue.

Claude Code, Codex and Gemini get this prompt as their first message on the
command line. Other agents are typed to once tty7 sees them running.

### What the document holds

No model writes the document. tty7 puts it together from what it already
knows, so the same inputs always produce the same file:

| Section | Comes from |
|---|---|
| Original goal | The session's first prompt, read from the agent's transcript (Claude Code, Codex, Qoder, CodeBuddy). For other agents, or when the transcript can't be read, the tab's title, labelled as such |
| Last status | The agent's status and last message from its [hooks](/agents/status) |
| Repository | Branch, `git status --short` and `git diff --stat HEAD` |
| Recent terminal output | The last 80 lines of the pane |
| Next steps | An empty checklist to fill in before the new agent reads it, if you want to |

### Where it's written

tty7 only writes into a repository that already ignores `.tty7/`, so a handoff
can't end up in a commit:

- **The repository ignores `.tty7/`**: `<repo>/.tty7/handoffs/<time>-<from>-to-<to>.md`.
- **Otherwise, or outside a repository**: `<config dir>/handoffs/<repo name>/…`,
  for example `~/.config/tty7/handoffs/my-app/`. The notification says which.

tty7 never edits `.gitignore` for you. To keep handoffs inside a repository, add
`.tty7/` to its ignores yourself.

A new tab opened by a handoff shows *Handed off from …* in its hover card while
the window stays open.

<Warning>
  Handoff works on this computer's panes only. A pane on a
  [remote machine](/remote/workspaces) or over SSH has its transcript and
  repository on the other side.
</Warning>

## Copy the session id

**Copy Session ID** — in the tab's right-click menu, beside *Copy Working
Directory*, and in Search Everywhere — puts the agent's native id on the
clipboard. Paste it into `codex resume`, a bug report, or another tool.
